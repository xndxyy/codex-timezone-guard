# Codex Timezone Guard — 技术设计

日期：2026-10-15（America/Phoenix）。范围 A 已批准；用户已明确要求在新目录执行本技术设计。项目仅处理 Codex 桌面端时区，不延伸分析模型访问错误。

## 1. 用户流程

下载便携 EXE → 查看首次联网披露 → 自动探测并预选 IANA 时区 → 查看网络来源、时间预览与候选客户端 → 点击“保存并启动 Codex”。手动选择/搜索时区始终可用。自动预选不是静默改动：本次时区在启动前可见，启动由用户点击触发。

客户端已运行时提示用户保存工作并自行退出；启动器不结束进程。检测或权限失败时允许重试与查看脱敏诊断，不悄悄猜测时区。网络出口在 Codex 使用期间变化时，首版不自动重启或热切换，只在下一次检测/启动时重新判定。

## 2. 实现选择与取舍

推荐 **C# / .NET 10 + Windows Forms**：已有本地 SDK 与 Windows Desktop 引用包，可以保持 GUI、HTTP/JSON、时区、测试与进程接口在一套技术栈。提供 self-contained 单文件 EXE，使用者无需另装 .NET。代价是捆绑运行时的文件比 Rust 原生程序大，体积与冷启动耗时应在构建后实测，不提前承诺。

替代方案：

1. 上游 Flutter + Rust：界面与部分兼容逻辑成熟，但本机缺少相应工具链，且目录式运行包与本项目单 EXE目标不同；参考算法与许可证，不整包复制皮肤/账户功能。
2. Rust + Win32：EXE 可更小，但当前缺工具链，需要额外安装与维护；不是首版最高效路线。
3. 修改 Codex ASAR、注入页面脚本或常开 CDP：版本耦合与安全面更大，不作为默认方案。

## 3. 模块与接口

- **TimezoneCatalog**：验证 IANA ID，解析 Windows 对应时区并计算预览；不靠国家名或固定 UTC 偏移猜时区。
- **SettingsStore**：只保存模式、IANA ID、经验证的目标标识与用户确认项；原子写入，不保存公网 IP/完整环境。
- **ProxyResolver**：按目的 URL 只读解析当前用户系统代理/PAC；返回直连、明确代理或不可解析，而非修改注册表。
- **ProbeTransport**：带取消、超时、大小限制、TLS 验证的无认证 HTTPS 请求；明确报告失败，不向 Codex 请求附加登录信息。
- **EgressDetector**：解析目标探测的 IP、来源、地址族和观测时间；与一般 IP 查询结果分离。
- **GeoLocator**：按明确 IP 请求地理定位，验证回显 IP 与 IANA 字段，再给出推荐；不混淆地理库误差与运行时设置成功。
- **DetectionCoordinator**：管理一次检测生命周期，丢弃已取消/过期结果，生成一致/矛盾/失败状态。
- **CodexDiscovery / Launcher**：区别桌面应用与 CLI，验证目标路径/包身份和既有进程，创建只修改子进程的环境。
- **MainWindow / DiagnosticReport**：中文操作、错误恢复、脱敏状态与诊断导出；不持有登录凭据。

核心模块不依赖 GUI 控件；传输、时钟、配置目录和启动后端可替换，以便无网络、无真实 Codex 地测试。

## 4. 规则代理：能做什么，不能声称什么

首选探测固定目标 `https://chatgpt.com/cdn-cgi/trace`，辅助目标 `https://api.openai.com/cdn-cgi/trace`。它们不是官方稳定的 Codex 诊断 API：403/404、挑战页、缺字段、迁移或不支持时必须安全失败，不尝试绕过验证。地址白名单不接受任意用户 URL；不转发认证 Cookie、Authorization 或 Windows 凭据。

请求前按每个目的 URL 解析系统代理/PAC。显式 PAC 失败不能自动降级直连。重定向默认不跟随，避免改变探测目的地。首版范围为系统直连、HTTP/HTTPS 代理、PAC 与现有 TUN；SOCKS-only 系统配置标为不支持并给出提示，可使用代理软件已有的 HTTP/mixed 接口，但启动器不代改其配置。TUN 路由由系统决定，不关闭或重配它。

探测获得的 IP 才是地理定位的查询参数。通用 IP 服务若作为参考，不可替代失败的目标探测而产生自动“已确认”结果；不使用 Cloudflare `colo` 字段推断用户城市/时区。

结果分为：

- **目标探测一致**：目标返回可解析公网 IP，重复探测/可用辅助目标未发现不同出口，地理服务给出有效 IANA ID。界面可自动预选，但文案是“基于目标域名探测的建议”。
- **出口存在差异**：同目标重复请求/不同目标/地址族给出不同出口。首版不擅自从负载均衡中任选节点；提示手动确认与再次检测。
- **无法确定**：目标不支持探测、网络失败、代理无法解析、限流、定位字段无效或只有一般 IP 网站的结果。保持手动入口，不覆盖已保存的手动时区。

任何状态都不声称“已证明 Codex 全部请求使用此 IP”。探测由启动器发起，无法天然复制按进程/可执行文件/UDP/动态节点制定的全部规则。首版不读取代理订阅/节点密码，不操作代理控制 API，不为了保证出口强行安装私有代理内核。用户若只允许按 `Codex.exe` 代理、不给启动器同等访问路径，自动判断可能无法完成；这属于透明的手动兜底场景。

## 5. IP 定位服务与隐私

默认定位后端为固定 HTTPS `https://ipwho.is/{observed-public-ip}`，仅解析成功标志、回显 IP、地点文本和 `timezone.id`。必须校验回显 IP 等于明确查询的 IP。该免费服务没有可用性承诺，遇到 429/Retry-After 时停止本轮，不轮询冲击服务、不申请付费额度。未计划内置公开 API 密钥。

首次联网前说明：目标站点会接收正常网络请求；定位服务会收到查询 IP 和发请求的出口 IP。UI 可展示本轮完整 IP，关闭/重新检测后不保证保留；配置与普通诊断不存原始 IP。缓存只用于界面提示且明确标记，不能充当新的自动出口证明。默认日志无查询 URL 原文、代理用户名/密码、PAC 内容、完整文件环境、账号信息或响应体。仅向固定白名单 HTTPS 服务发送请求，拒绝重定向、无效证书和过大数据。

## 6. A 方案进程隔离

普通桌面安装采用无 shell 的新进程启动，复制环境后只替换子进程 `TZ` 并移除误继承的 `ELECTRON_RUN_AS_NODE`。不得使用 `setx`、`tzutil /s`、系统/用户环境变量写入或全局 `TZ`。不覆盖用户现有代理变量，也不在首版强制设置 Codex 的代理。

Windows Store/MSIX 候选先枚举包身份、应用清单与路径；每次启动重新发现当前版本，不能永久信任旧路径。参考上游的受控启动流程：通过 CreateProcessW 以挂起状态创建带独立 Unicode 环境块的新进程，在执行客户端代码前以 GetPackageFullName/GetApplicationUserModelId 核对身份，吻合才 ResumeThread；失败仅清理本工具尚未恢复执行的新进程。遇到身份缺失/权限异常时停止并说明限制，不改 WindowsApps ACL、不自动提升权限、不采用包调试器注册。已验证支持的具体安装渠道与版本才进入兼容列表。

必须检查 Codex **桌面路径/包身份**，不能把所有 `codex.exe` 当作桌面端。候选冲突、身份不明或已有实例检查权限不足时拒绝自动启动；手动选择也不能绕过桌面身份校验。只清理本工具创建且尚未执行的失败测试/挂起子进程，绝不结束用户已运行实例。

用户已允许子进程继承，但共享/已运行的后台 daemon 不一定得到本次环境。通过 Windows 原生 API 取时区的组件也可能继续得到系统值。运行时是否采用 `TZ` 要独立验证，不能把环境变量写入当作所有 Codex 组件/服务端时区已切换。

## 7. UI 与错误处理

首版为一个中文窗口：顶部显示当前模式与系统/目标时间；中部显示检测状态、来源和规则模式提醒；下部为可搜索 IANA 时区、客户端选择、“重新检测”和“保存并启动”。首次使用展开隐私说明，失败后保持手动可用。

状态至少区分：未检测、检测中、自动建议、需要手动确认、目标已启动但时区未验证、启动失败。不得把“已创建进程”标成“时区已生效”。操作可取消，后台任务不得冻结窗口，重复点击启动受单实例/串行保护。保存配置失败时不报告已保存。

## 8. 验收与证据

1. **纯逻辑**：IPv4/IPv6、保留地址、IANA 校验、夏令时、配置损坏/原子写入、错误/取消/状态竞争。
2. **模拟网络**：目标与通用 IP 服务不同出口、403/404/429、PAC 失败、不同目标矛盾、定位回显 IP 不符、跨地址族差异、响应过大与请求取消。
3. **进程夹具**：受控 EXE 输出收到的 `TZ`、日期格式和 PID；证明父进程、独立探针、Windows 时区与注册表环境未变；故意启动失败也不误报。
4. **本机网络**：经用户已授权的检测任务进行无凭据探测，仅记录脱敏结果；真实失败应保留，不包装为通过。
5. **真实 Codex**：需要用户主动保存工作并退出后检查启动；若客户端允许开发者工具，以 `Intl.DateTimeFormat().resolvedOptions().timeZone` 与日期偏移验证相关运行时。不能进行的检查列为未验证，不通过向模型询问当前时间代替。
6. **打包/发布**：从源码测试、单文件启动/自检、生成 SHA-256、检查无秘密与 SNN 文件、远端资产确认。未完成真实兼容验证时仅发带边界的预发布版，不称稳定兼容所有渠道。
